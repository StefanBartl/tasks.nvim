1. INTRODUCTION                                                    *tasks_nvim*

One Markdown file per task (flat YAML frontmatter), one generated overview per
area (`<area>/ROADMAP/TASKS.md`), finished tasks in `<area>/Backlog/`. The
engine is pure Lua; |:Tasks| is the editor front end (dashboard, form,
preview); `scripts/tasks.lua` is the headless CLI. Both use the same engine.

Capturing is one call with a title and never asks for more. A task without
blockers, plan or estimate is valid and stays visible everywhere.

==============================================================================
2. REQUIREMENTS                                         *tasks_nvim-requirements*

  Neovim 0.10+ and lib.nvim (required).
  Optional: snacks.nvim (dashboard), mdview.nvim (browser preview), ui.nvim
  (themed confirmations), pickers.nvim (`:Tasks folder`), cascade.nvim (form),
  git (dates for `--stale=refs`).

3. SETUP AND CONFIGURATION                                    *tasks_nvim-setup*

>lua
  require("tasks_nvim").setup({
    vault = "~/vault",
    extra_areas = { "ALL" },
    dashboard = { watch = true, debounce_ms = 250, backend = "auto" },
    staleness = { git_timeout_ms = 20000, budget_ms = 30000, repo_bases = {} },
    ci = { lint_timeout_ms = 120000 },
    next = { popup = true, cdx_hint = true },
    chain = { marker_docs = {} },
    steps = { ask_finish = false },
    quick_wins = { min_value = 4, max_effort = "S" },
    lists = {},
  })
<

  vault                    The vault folder (one folder per area). When unset
                           `$TASKS_VAULT` is read. There is no built-in path.
  extra_areas              Folders that are areas although they hold neither
                           `ROADMAP/` nor `Backlog/`. The headless CLI reads
                           `$TASKS_EXTRA_AREAS` (comma separated) for the same.
  dashboard.watch          Refresh the dashboard when task files change.
  dashboard.debounce_ms    Quiet period before a refresh (default 250).
  dashboard.backend        Picker of `:Tasks list`: "snacks", "kit" (lib.nvim, no snacks;
                           Alt-chord keys), "select", or "auto" (snacks if installed, else kit).
  staleness.git_timeout_ms One `git log` call is killed after this long.
  staleness.budget_ms      All git calls of one `--stale=refs` run together.
  staleness.repo_bases     Folders holding the repos by name (`<base>/<area>`).
  ci.lint_timeout_ms       The vault's `md_lint.lua` is killed after this long.
  ci.trust_vault_lint      Allow `ci` to run the vault's own `md_lint.lua`.
  next.popup               After `done`: a dialog with the next task (else a message).
  next.cdx_hint            Name ready tasks written `cdx` apart, never as your next task.
  chain.marker_docs        Documents whose `<!-- GENERATED:plan scope=... -->` blocks are
                           refreshed after a task is finished (only these files). The
                           headless CLI reads `$TASKS_MARKER_DOCS` (comma separated).
  quick_wins.min_value     A quick win has at least this value (1-5) ...
  quick_wins.max_effort    ... and at most this effort (`XS`..`XL` or days like `0.5d`).
  lists                    Named lists, `{ ["name"] = { effort = "<=S", value = ">=4",
                           sort = "roi", desc = "..." } }`: the option words of
                           `:Tasks list`. Run with `--list={name}` or `tasks list @name`.
                           A later `setup()` replaces the set; see :Tasks lists.
  steps.ask_finish         In a task buffer, ticking the last `## Plan` step asks to finish
                           the task (off by default: it adds an autocommand).
  keys.dashboard           Dashboard list keys: action = key, or false.
  keys.dashboard_input     Dashboard input-window keys (normal and insert).
  keys.form                Keys of the `:Tasks new` form.
                           Actions: see |tasks_nvim-keys|.

A wrong key or value is ignored with a message and listed in
`:checkhealth tasks_nvim`; the default stays.

`vim.g.tasks_nvim_no_command = true` keeps the plugin from registering |:Tasks|.

4. COMMANDS                                                             *:Tasks*

  :Tasks list [{area}|all] [filters] [--sort=] [--to=] [--format=] [--force]
      Open tasks: a dashboard, or a table to a buffer, the clipboard, the
      quickfix list, a file, a browser preview. An existing file is only
      overwritten with `--force`.
      Filters: --status= --prio= --effort= --kind= --category= --severity=
               --value=4,5|>=4 --actor=cdx|me|pair|none
               --tag= --stale=<days>|refs --blocked

  :Tasks new [{area} [{title}...]] [kind= prio= effort= value= actor=
              tags= category= severity= status=] [--folder]
      Without arguments a Markdown form (`<C-s>` submits).

  :Tasks set {id} {key}={value} ...      Change frontmatter; an empty value
                                         removes the key.
  :Tasks done {id} [done_in= date=] [--yes]
                                         Finish and move to `Backlog/`; names
                                         what it freed and offers the next task.
  :Tasks plan [{area}|all] [--for={id}|--plan={id}] [filters] [--ready] [--with-steps]
              [--format=] [--to=] [--write={file} [--scope=] [--check]]
                                         Ready now, decisions by leverage,
                                         stages, critical path.
  :Tasks planfile {area} {title...} [--areas=] [--phases=] [--gate=hard] [--target=]
                                         Create a plan file under `ROADMAP/plans/`.
  :Tasks next [{area}|all] [--n=] [--actor=]
                                         The best ready task, with the reason.
  :Tasks estimate [{area}|all] [--for={id}] [filters] [--walk]
                                         Sums of effort and value, what is
                                         missing; `--walk` asks for them.
  :Tasks lists                           Pick a named list and open it as the dashboard.
  :Tasks list --list={name} [more options]   Run a named list; options you give win.
  :Tasks quickwins [{area}|all] [filters] [--to=] [--format=md|tsv|ids] [--by-actor] [--paths] [--report={file}]
                                         The quick wins, best return first, and the
                                         small tasks that miss a value.
  :Tasks attach {id} {file} [name=]      Copy a file into `assets/`.
  :Tasks folderize {id}                  Make a plain task a folder task.
  :Tasks template [--to=]                The task file template.
  :Tasks open {id}                       Open the task file.
  :Tasks preview {id}                    Browser preview (mdview.nvim).
  :Tasks index [{area}] [--all] [--check]
                                         (Re)write the generated overviews;
                                         `--check` writes nothing.
  :Tasks folder {area} [folder] [--action=] [--list] [--to=]
                                         Picker over a folder of an area.

An id is `<area>/<slug>`. `<Tab>` completes verbs, areas, ids, values and the
settable keys. Details: docs/COMMANDS.md. Scenarios: docs/WORKFLOWS.md.

5. DASHBOARD AND FORM KEYS                                       *tasks_nvim-keys*

No global key is mapped. In the dashboard list (`g?` shows this):

  <CR> open   <Tab> mark   s status   p prio   D finish   f filter chip
  o sort      e export     gp preview  r rescan  gb backlog  gr roadmap
  gl lists (apply, save the current view as a list, rename or delete one)

In the input window the same actions are on `<M-s> <M-p> <M-d> <M-f> <M-l> <M-o>
<M-e> <M-r> <M-b> <M-m> <M-v> <M-?>` (they shadow some snacks defaults).

In the task form: `<Space>`/`<CR>` tick a line, `<C-s>` submit, `q`/`<C-q>`
cancel (asks when text was typed), `g?` help.

6. TASK FILE FORMAT                                            *tasks_nvim-format*

>markdown
  ---
  title: Fix the thing
  status: open          # doing | decision | blocked | open | parked
  kind: bug             # feature | task | bug | idea | research
  prio: 2               # 1 (highest) .. 3
  effort: S             # XS S M L XL, or 0.5d, 3d
  tags: [ui]
  category: [bug]       # bug security performance docs ruleset
  blocked_by: [other-area/other-task]
  refs: [lua/foo/init.lua]
  created: 2026-10-05
  updated: 2026-10-05
  ---
  One summary paragraph, then free Markdown.
<

Only `title` and `status` are required. Unknown keys are kept when a file is
rewritten. Full reference: docs/ENGINE.md.

7. HEADLESS CLI                                                 *tasks_nvim-cli*

>sh
  nvim --headless -u NONE -l scripts/tasks.lua list --status=doing
  nvim --headless -u NONE -l scripts/tasks.lua done my-area/slug --done-in=repo@abc
  nvim --headless -u NONE -l scripts/tasks-ci.lua
<

The vault is `--vault=<dir>` or `$TASKS_VAULT`. Exit codes: 0 success, 1 a
finding or failed operation, 2 a usage error. `scripts/tasks-ci.lua` runs
`check`, `index --check` and the vault's `md_lint.lua`. That script is RUN, so
it is refused unless you pass `--trust-vault-lint` (or `--md-lint=<own copy>`).

A task file that is a symbolic link or a junction is not read (`check` reports
`symlink-task`), and a folder of the vault that leads out of it is not scanned.

8. HEALTH                                                     *tasks_nvim-health*

`:checkhealth tasks_nvim` reports Neovim and lib.nvim, the resolved vault and
its areas, options that `setup()` ignored, whether |:Tasks| is registered, and
which optional pieces are present.

9. MACHINE CONTRACT                                       *tasks_nvim-contract*

For apps, agents and pipelines: versioned JSON documents, read only. The
shapes, rules and errors are in docs/CONTRACT.md; the JSON Schemas are in
`schemas/tasks-export/1/`.

>sh
  nvim --headless -u NONE -l scripts/tasks.lua call hello
  nvim --headless -u NONE -l scripts/tasks.lua call snapshot
  nvim --headless -u NONE -l scripts/tasks.lua call list --params='{"limit":20}'
  nvim --headless -u NONE -l scripts/tasks.lua call task --params='{"id":"area/slug"}'
<

Methods: `hello`, `snapshot`, `list`, `task`, `next`, `areas`. Exit codes: 0
an answer, 2 `invalid_argument`, 1 any other error (a `tasks.error`
document, also on stdout). From Lua: `require("tasks_nvim.api").call()`,
which never throws. A document has no path of this machine, a missing
number is unknown (never 0), a broken task is listed with `valid: false`,
and each task carries an `etag`; `rev` and `digest` say whether anything
changed.
